# TRM §4.3.3 外部存储器 / 高速缓存（ESP32-S3 TRM v1.8）

## §4.3.3.1 外部存储器地址映射（原文摘要）

> CPU 借助高速缓存 (Cache) 来访问外部存储器。Cache 将根据内存管理单元 (MMU) 中的信息把
> CPU 指令总线或数据总线的地址变换为访问片外 flash 与片外 RAM 的实地址。经过变换的实地址
> 所组成的实地址空间最大支持 1 GB 的片外 flash 与 1 GB 的片外 RAM。
>
> 通过高速缓存，ESP32-S3 一次最多可以同时有：
> - 32 MB 的指令总线地址空间，通过指令缓存 (ICache) 以 **64 KB 为单位**映射到片外 flash
>   或片外 RAM，支持 4 字节对齐的读访问或**取指访问**。
> - 32 MB 的数据总线地址空间，通过数据缓存 (DCache) 以 64 KB 为单位映射到片外 RAM，
>   支持单字节、双字节、4 字节、16 字节的读写访问。这部分地址空间也可以用作只读数据空间，
>   映射到片外 flash 或片外 RAM。

表 4.3-2 外部存储器地址映射：

| 总线 | 低地址 | 高地址 | 容量 | 目标 |
|---|---|---|---|---|
| 数据 | 0x3C00_0000 | 0x3DFF_FFFF | 32 MB | DCache |
| 指令 | 0x4200_0000 | 0x43FF_FFFF | 32 MB | ICache |

**紧跟在表后面的一句话（很重要）：**

> 说明：只有获取到外部存储器的访问权限，CPU 访问外部存储器时才可以被响应。
> 关于权限管理的更多信息，请参考章节 15 权限控制 (PMS)。

## §4.3.3.2 高速缓存（原文摘要）

> ESP32-S3 采用双核共享 ICache 和 DCache 结构，以便当 CPU 的指令总线和数据总线同时发起
> 请求时，也可以迅速响应。
>
> 当两个核的指令总线同时访问 ICache 时，由仲裁器决定谁先获得访问 ICache 的权限；当两个核
> 的数据总线同时访问 DCache 时，由仲裁器决定谁先获得访问 DCache 的权限。**当 Cache 缺失时，
> Cache 控制器会向外部存储器发起请求**，当 ICache 和 DCache 同时发起外部存储器请求时，由
> 仲裁器决定谁先获得外部存储器的使用权。
>
> ICache 的缓存大小可配置为 16 KB 或 32 KB，块大小可以配置为 16 B 或 32 B；
> DCache 的缓存大小可配置为 32 KB 或 64 KB，块大小可以配置为 16 B、32 B 或 64 B。

## §4.3.3.3 Cache 操作（原文摘要）

1. **Write-Back**：把 Cache 中"脏块"的脏标记抹除，并将数据同步到外部存储器。只有 DCache 有。
2. **Clean**：抹除脏标记但不写回。只有 DCache 有。
3. **Invalidate**：删除 Cache 中的有效数据（即使脏块也不写回）。分自动失效
   (Auto-Invalidate) 和手动失效 (Manual-Invalidate)。**ICache 和 DCache 均具有此功能。**
4. **Preload**：预取，把指令和数据提前加载到 Cache，最小单位 1 个块。分手动和自动。

> 注：文档全章没有"修改 MMU 表项之前必须先做某个特殊操作"的成文要求；
> NuttX 的 S3 移植代码里有注释提示"写 MMU 寄存器时应挂起 cache"，可作为实践参考。
