# TRM §15 权限控制 (PMS)（ESP32-S3 TRM v1.8）

## §15.1 概述（原文）

> ESP32-S3 中所有的片内存储器、片外存储器、及外设均支持访问权限管理，CPU 必须拥有相应访问
> 权限才能访问相应的从设备，从而保护数据和指令不被非法读取、改写和取指。

## §15.2 主要特性（原文节选，注意最后一条）

> 支持片外存储器的权限管理
> - SPI1 访问外部存储器的权限控制
> - GDMA 访问外部存储器的权限控制
> - **CPU 通过 CACHE 访问外部存储器的权限控制**

## §15.5 片外存储器权限管理（原文）

> 在 ESP32-S3 中，存在三条访问外部存储器的数据路径：
> - CPU 通过 SPI1 访问
> - **CPU 通过 CACHE 访问**
> - GDMA 访问
>
> **SPI1、GDMA 或 CACHE 如需访问外部存储器，必须首先获得相应的访问权限。**
> - 虚线框 0 对实地址做权限检查
> - 虚线框 1 对 GDMA 访问的虚地址做权限检查
> - **虚线框 2 对 CPU 访问 CACHE 的请求做虚地址检查**

### §15.5.1 外部存储器实地址空间划分

> 可以将外部存储器 (flash + SRAM) 的实地址划分为共 8 个区域：
> - flash 划分为 4 个区域，每个区域的大小均为 64 KB 的倍数。
> - SRAM 划分为 4 个区域，每个区域的大小均为 64 KB 的倍数。
> - 各区域的起始地址也均需以 64 KB 对齐。

区域范围寄存器：

| 地址段 | 起始地址 | 长度 |
|---|---|---|
| flash 区域 n (0~3) | `SYSCON_FLASH_ACE_n_ADDR_REG` | `SYSCON_FLASH_ACE_n_SIZE_REG` |
| SRAM 区域 n (0~3)  | `SYSCON_SRAM_ACE_n_ADDR_REG`  | `SYSCON_SRAM_ACE_n_SIZE_REG` |

### §15.5.2 外部存储器的权限配置（原文）

> flash 的 4 个区域和外部 SRAM 的 4 个区域均可单独配置权限。软件可以通过寄存器
> `SYSCON_SRAM_ACEn_ATTR_REG` 和 `SYSCON_FLASH_ACEn_ATTR` 配置对应区域的权限。

| 地址段 | 权限配置寄存器 | CACHE 安全世界 [2:0] | CACHE 非安全世界 [5:3] | SPI1 [7:6] |
|---|---|---|---|---|
| flash 区域 n | `SYSCON_FLASH_ACEn_ATTR` | ✓ | ✓ | ✓ |
| SRAM 区域 n  | `SYSCON_SRAM_ACEn_ATTR_REG` | ✓ | ✓ | ✓ |

> A 配置顺序为 **W/R/X**。
> C 举例而言，配置这些比特位为 `0b010` 代表 CACHE 在安全世界中对 flash 的区域 n
> **有读取权限，但没有写入和取指权限**。

## 对本项目的意义（重要）

我们的现象是「跳进 flash 或数据读 flash 都返回 0」，而 TRM 明确写了
**未获得权限 ⇒ 访问不被响应**。也就是说：

- 如果 `SYSCON_FLASH_ACEn_ATTR` 里 CACHE 那 3 位（W/R/X）没有给到我们代码所在的
  flash 区域，取指就会被"静默拒绝"，表现为取回 `0x00000000`（Xtensa 里是 `ill`），
  这和我们实测的 `exccause=0 / excvaddr=0` 完全吻合。
- 需要检查：我们的镜像在 flash 0x20000 起、IROM 段在 flash 0x30000，这些地址落在哪个
  ACE 区域里，以及该区域 CACHE 位的 **X（取指）和 R（读取）** 是否被允许。

**这是目前最值得验证的一条**（比继续折腾 cache/MMU 寄存器更有希望）。

## 实测结论（2026-xx，真板 JTAG）

`SYSCON_FLASH_ACEn_*` 在**我们自己的固件**和**能正常跑 IROM 的原厂固件**上逐字相同：

```
ATTR0..3 = 0x000000ff   (全部权限：CACHE 安全/非安全世界 W/R/X + SPI1 W/R)
ADDR0..3 = 0x00000000 / 0x10000000 / 0x20000000 / 0x30000000
SIZE0..3 = 0x00001000
```

⇒ **PMS 不是我们的问题**（flash 区域对 CACHE 完全开放），这条最有力的线索也排除了。
